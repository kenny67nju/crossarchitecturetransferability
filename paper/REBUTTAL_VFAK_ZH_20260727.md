# 给 Reviewer Vfak 的回复

感谢审稿人细致的技术审阅，并认可论文的实践问题诊断、oracle regret 指标、广泛实验覆盖和诊断性消融。审稿意见指出了真实存在的歧义和两处表述错误。下面按照 review 中的问题顺序逐项回复。

## 1. SA_k 的精确定义与异构维度

"固定参考编码器"这一表述不正确。我们固定的是参考**数据集** R（STL-10），而不是所有候选模型共用的某个编码器。

对于每个候选编码器 m，我们提取并中心化目标特征 H_(m,T)（形状 n_T × d_m）和参考特征 H_(m,R)（形状 n_R × d_m）。两者都由同一个候选编码器 m 产生，因此特征维度总是相同。方法不会把某个编码器的右奇异子空间与另一个编码器的右奇异子空间直接比较。

令 H_(m,T) = U_T Σ_T V_T^⊤ 和 H_(m,R) = U_R Σ_R V_R^⊤ 为两者的 SVD，且 k_m = min(k, n_T, n_R, d_m)。V_T 和 V_R 取前 k_m 个右奇异向量，实际实现的 alignment 为

    SA_k(H_(m,T), H_(m,R)) = (1/k_m) · ‖V_T^⊤ V_R‖_F²
                           = (1/k_m) · Σ_{i=1..k_m} cos²(θ_i),

其中 θ_i 是 principal angles。这里的 V 是候选模型自身 d_m 维特征空间中的主右奇异方向。不同候选模型可以具有不同的 d_m，但跨候选模型只比较最终的标量 SA_k 和 SSR 分数，不需要跨编码器公共投影。

这也消除了 Proposition 3 的歧义：如果只对 H_(m,T) 做右旋转，而不对 H_(m,R) 施加相同旋转，两者的主角 alignment 会改变。实现中不使用左奇异向量。

候选模型 m 的完整计算流程是：使用 m 提取目标和 STL-10 特征；分别中心化；计算前 k_m 个右奇异向量；计算上述 alignment；计算目标特征的 effective rank；最后返回一个标量分数。

## 2. SCR/SSR 不一致以及实际使用的分数

审稿人的判断正确：将参数直接代入原稿的一般 SCR 公式，不能得到所展示的 SSR‡ 公式。这是表述错误，两种表达式并不等价。

生成论文 SSR 主结果所实际使用的 effective rank 和分数是

    p_i = σ_i / (Σ_j σ_j),
    r_eff(H) = exp( −Σ_i p_i · log p_i ),

    SSR‡(H, T) = [ log r_eff(H) − log SA_k(H, H_ref) ] / log C(T).

代数一致的一般形式应为

    SCR(H, T; β, g) = [ log r_eff(H) + β · g(SA_k) ] / log C(T).

取 g(s) = −log s、β = 1，可以精确得到上面的 SSR‡ 表达式。对于固定目标任务，1/log C(T) 对所有候选相同，不改变排序。

## 3. 修正后的 Marchenko–Pastur 推导

我们同意原稿中的推导存在错误：它混用了归一化平方奇异值和 RankMe 的奇异值归一化，遗漏了审稿人指出的 size-biased 项，并错误声称 MP support 在所有长宽比下都远离零。

令 H 为 n×d 的各向同性随机矩阵，并采用标准 MP 纵横比 ρ=d/n（原稿采用其倒数 γ=n/d）。令 λ_i=σ_i²/(nσ_0²)，其中 σ_0² 是矩阵元素方差。这里取 HᵀH/(nσ_0²) 的全部 d 个特征值；当 d>n 时也包括零特征值。其经验分布几乎必然收敛到 MP 分布 μ_ρ。定义

    m_(1/2) = ∫ √x dμ_ρ(x).

RankMe 中公共尺度 √n σ_0 会抵消，因此 p_i=√λ_i/Σ_j√λ_j。令 S_d=(1/d)Σ_j√λ_j，则 S_d→m_(1/2)，并且有限维下有精确恒等式

    H(p) = log d + log S_d − [1/(2S_d)]·(1/d)Σ_i √λ_i log λ_i.

取 MP 极限后得到

    H(p) = log d + log m_(1/2) − [1/(2·m_(1/2))]·∫ √x log x dμ_ρ(x) + o(1).

这里包含了必要的 size-biased spectral term。采用 √0 log 0=0 的约定后，即使 MP 分布的支撑到达零或在零点具有原子，该积分仍然有限；对任意固定 0<ρ<∞，m_(1/2)>0。因此

    r_eff(H)/d → exp{ log m_(1/2) − [1/(2·m_(1/2))]·∫ √x log x dμ_ρ(x) } = c(ρ)>0.

从而对固定 ρ 有 r_eff(H)=Θ(d)。用原稿的记号，该常数应写成 c(1/γ)。该结论也覆盖 d>n；此时因 r_eff≤n，必有 c(ρ)≤1/ρ。

## 4. Corollary 2 的适用范围

我们同意"任意 rotation-invariant score"的说法过宽。旋转不变性只说明分数依赖奇异值，并不能推出它关于 d 单调。维度归一化 effective rank、condition number 以及刻意构造的非单调谱形状统计量都是反例。

合理的结论应限制为：连续、未进行维度归一化、并且在各向同性极限下随有效谱维数增长的 spectral-diversity/effective-rank functional。RankMe 属于该类。VNE 需要单独考虑其归一化方式，任意旋转不变量不应被 Corollary 覆盖。

## 5. DiSCO 协议与修正后的评估

审稿人正确指出了评估协议问题。官方 DiSCO 使用**目标任务真实标签**构造类条件协方差和后验量。在我们的评估中，它没有使用伪标签或无标签聚类。因此，DiSCO 是**需要标签的比较方法**，不是 label-free baseline，不能与 RankMe 或 SSR‡ 在相同标签预算下直接比较。

内部核查还发现，旧实现没有忠实复现官方的类条件 Mahalanobis posterior 算法。我们使用 PCA-128 预处理重新实现官方流程，补跑全部失败的模型—任务特征，并补齐此前缺失的 22 个 LP 单元。最终 MV 和 EX 表分别包含 660/660 和 510/510 个完整单元。

为了与下文的共同任务集合保持一致，VTAB 数值统一排除 STL-10；其他模型池使用各自完整的目标任务集合。两个 group 设置下修正后的 DiSCO regret 为：

| Pool | G=6 | G=8 |
|---|---:|---:|
| MV | 0.146 | 0.146 |
| VTAB（7 个目标；排除 STL-10） | 0.061 | 0.044 |
| SSL | 0.045 | 0.042 |
| EX | 0.045 | 0.049 |

这些结果使原稿中的 DiSCO 聚合结果及其显著性比较失效。SSR‡ 在 MV 上仍然更强（0.098 对 0.146），但 DiSCO 在 EX 上更强（0.045–0.049 对 0.060），并且在 VTAB 和 SSL 上也很有竞争力。因此我们撤回"SSR‡ 普遍优于 DiSCO"的主张，也撤回用 d_max/d_min ≈ 7 在二者之间做选择的规则。

核心的同标签预算无标签比较应是 SSR‡ 与 RankMe。

## 6. STL-10 参考/目标统计口径

审稿人正确指出，原稿的 23-task 统计口径不一致。对于不需要参考集的方法，STL-10 被当作普通 VTAB 目标；而当 STL-10 同时作为目标和参考时，SSR‡ 没有定义。因此不能把该单元视为独立的 SSR‡ 评估。

公平的共同任务分析应对**所有**方法统一排除 STL-10：5 MV + 7 VTAB + 10 EX = 22 个任务单元。在该共同集合上：

- SSR‡ 平均 regret 为 0.071；
- RankMe 平均 regret 为 0.166；
- 配对差值为 −0.095，95% CI 为 [−0.160, −0.037]，采用双侧、任务级 paired bootstrap 检验得到 p = 0.0002。

因此，SSR‡ 相对 RankMe 的核心结论不变，但 Table 7 的 23-task 表述以及使用不一致任务集合的统计量都应修正。

## 7. 两阶段结论与证据强度

我们同意，原稿对 one-third-cost 的表述过于宽泛。直接的多变体证据只有五个 MV 任务。在该基准上：

- flat SSR‡：regret 0.098，平均成本 118.8 次前向评估；
- SSR‡ → RankMe：regret 0.102，平均成本 38.0。

这说明该 pipeline **在这一基准上**以约三分之一成本保持了接近的 point-estimate quality。它只是 proof of concept，不是适用于任意异构模型库的一般 cost-quality 保证；还需要更多多变体模型池和任务验证。

最后，目前不存在从 SA_k 到 linear-probe accuracy 的形式化界。支持该机制的是经验结果：在 126 个 VTAB 架构—任务 pair 上，SA_k 与通用参考子空间之外的类间方差比例的相关为 −0.964，而该比例又能正向预测 LP accuracy。这是机制证据，而不是下游性能定理。

综上，核查后可成立的贡献范围更窄：RankMe 在异构架构池中受到显著宽度混淆；SSR‡ 是一种无超参数、无标签的跨 family 校正，在共同评估集合上显著优于 RankMe。我们不主张它普遍优于需要标签的方法，不主张 alignment 与准确率之间存在理论保证，也不主张两阶段 pipeline 具有一般部署保证。
