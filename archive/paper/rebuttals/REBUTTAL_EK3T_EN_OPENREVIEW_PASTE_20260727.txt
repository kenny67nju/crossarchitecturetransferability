We thank the reviewer for recognizing the practical importance of the problem, the width-confounding diagnosis, the thorough empirical validation, and the originality of using subspace geometry as a label-free correction. We agree that the submission did not define the alignment term clearly enough and did not provide adequate guidance for reference selection or the method's scope.

1. Clarification: we fix a reference dataset, not a reference encoder

The phrase "fixed reference encoder" is misleading, and our presentation likely caused it. To be precise: we fix a reference DATASET $R$, while each candidate encoder processes both the target and reference datasets.

For candidate encoder $m$, we extract target features $H_{m,T}\\in\\mathbb{R}^{n_T\\times d_m}$ and reference features $H_{m,R}\\in\\mathbb{R}^{n_R\\times d_m}$, where $R$ is STL-10 in the main experiments. The selection scores audited below use direct (uncentered) SVD, matching the submitted main scoring pipeline. Because both matrices are produced by the same candidate, their dimensions match; we do not align features from different encoders.

This distinction is important for interpreting the method. The reference features describe which directions candidate $m$ uses for generic visual variation; the target features describe which directions the same candidate uses on the downstream data. Their overlap is measured within $m$'s own representation space.

2. Formal definition of $\\mathrm{SA}_k$

Let $H_{m,T}=U_T\\Sigma_T V_T^\\top$ and $H_{m,R}=U_R\\Sigma_R V_R^\\top$ be the SVDs, and set $k_m=\\min(k,n_T,n_R,d_m)$. With $V_T$ and $V_R$ collecting the top-$k_m$ right-singular vectors, the implemented alignment is

For display clarity, let H(m,T), H(m,R), and k(m) denote the target features, reference features, and retained rank for candidate m. Then

Formula: $\\mathrm{SA}(k;H(m,T),H(m,R))=\\frac{\\cos^{2}(\\theta(1))+\\cdots+\\cos^{2}(\\theta(k(m)))}{k(m)}.$

Here $\\theta_i$ are the principal angles between the top right-singular subspaces. The value lies in $[0,1]$: a larger value means that the candidate uses more similar dominant feature directions on the target and generic reference data.

The complete computation for each candidate is:

- extract target and reference features using that candidate;
- compute the two SVDs;
- retain the top $k_m$ right-singular vectors;
- compute the mean squared principal-angle cosine above;
- compute RankMe effective rank on the target features; and
- return the scalar SSR score.

The RankMe-consistent effective rank and the score used in the experiments are

Formula: $p_i=\\frac{\\sigma_i}{\\sum_j\\sigma_j},\\qquad r_{\\mathrm{eff}}(H)=\\exp\\Big(-\\sum_i p_i\\log p_i\\Big),$

Here effrank(H) is the effective rank and H(ref) is the reference-feature matrix.

Formula: $\\mathrm{SSR}^{\\ddagger}(H,T)=\\frac{\\log\\operatorname{effrank}(H)-\\log\\mathrm{SA}(k;H,H(\\mathrm{ref}))}{\\log C(T)}.$

Equivalently, the general family is

Formula: $\\mathrm{SCR}(H,T;\\beta,g)=\\frac{\\log\\operatorname{effrank}(H)+\\beta g(\\mathrm{SA}(k;H,H(\\mathrm{ref})))}{\\log C(T)}.$

Setting $g(s)=-\\log s$ and $\\beta=1$ gives the SSR expression exactly.

Only the resulting scalar score is compared across heterogeneous candidates. We will state this formal definition and the step-by-step computation explicitly in the revised main text, together with the reference-selection criteria below.

3. Criteria for selecting the reference dataset

We agree that reference selection was not principled enough in the submission. STL-10 is a practical default, not a theoretically optimal reference. We selected it because it is small, contains generic natural objects, is available to all candidate encoders, and is disjoint from the seven non-STL VTAB targets.

Our recommended criteria are:

- target disjointness: the reference must not be the evaluated target dataset;
- no target-performance feedback: neither target labels nor target accuracy should be used to select it;
- broad visual coverage: generic visual content is preferable to a narrow task-specific domain;
- stable subspace estimation: it should contain enough diverse samples to estimate the top-$k$ directions; and
- low reusable cost: reference features should be inexpensive to extract once and cache across targets.

The reviewer suggests accounting for the downstream domain. We agree with this direction, with an important constraint: domain adaptation of the reference must not use target labels or select the reference by observing target performance. A safe approach is to choose, before evaluation, a target-disjoint reference from the same broad modality (e.g., natural objects, medical images, or remote sensing), or to use a predetermined multi-reference ensemble. Learning or tuning the reference using target accuracy would turn reference selection into a supervised model-selection step.

The submitted ablation used the legacy squared-singular-value normalization; its Flowers-102 single-reference value $0.013$ additionally used the target as reference and is withdrawn. Recomputing with RankMe's stated normalization gives STL-10 regret $0.053$. A four-reference LOO median gives $0.051$: if the target is among STL-10, CIFAR-10, Flowers-102, or Pets, it is removed before aggregation. A centered-SVD sensitivity run gives LOO regret $0.044$, leaving the conclusion unchanged.

One reference requires one additional unlabeled feature-extraction pass per candidate, after which its features are cached and reused for every target. An $M$-reference ensemble requires $M$ reference-side passes; target-side cost is unchanged. We therefore recommend one generic, target-disjoint reference as the default and a small predetermined ensemble only when additional robustness justifies its cost.

4. Single-family degeneration and intended applicability

We agree that $\\mathrm{SSR}^{\\ddagger}$ does not provide a stable additional signal within a single architecture family. This is a real limitation. Within-family variants often have the same feature dimension and similar top-$k$ subspaces, so the alignment term has little discriminative variation.

The evidence supports a narrower operational role:

- use $\\mathrm{SSR}^{\\ddagger}$ to compare heterogeneous architecture families;
- use RankMe within one family; and
- in a mixed model zoo, use $\\mathrm{SSR}^{\\ddagger}$ to select the family and RankMe to select a variant inside it.

On the five-task MV multi-variant benchmark, $\\mathrm{SSR}^{\\ddagger}\\to$RankMe achieves regret $0.102$, compared with $0.098$ for flat $\\mathrm{SSR}^{\\ddagger}$, while reducing mean forward evaluations from $118.8$ to $38.0$. This supports the feasibility of this division of labor on MV, but it is not a general guarantee for arbitrary model zoos.

5. SSL, DiSCO, and the scope of the significance claim

We agree that the practical advantage is pool-dependent and that the submitted DiSCO comparison requires correction.

Our protocol audit confirms that official DiSCO uses target GROUND-TRUTH labels to form class-conditional covariance and posterior quantities. It is therefore a label-dependent comparator, not a label-free baseline. The fair label-free comparison is $\\mathrm{SSR}^{\\ddagger}$ versus RankMe.

The same-label-budget result remains supported. Excluding STL-10 gives $5$ MV $+\\,7$ VTAB $+\\,10$ EX $=22$ pool-task units. Correcting the VTAB table's legacy squared-singular-value effective ranks gives SSR regret $0.066$, RankMe $0.169$, and difference $-0.1025$. These units contain 10 unique target names, eight repeated across pools; a target-name-clustered bootstrap gives 95% CI $[-0.164,-0.039]$ and $p=0.00114$, while paired Wilcoxon gives $p=0.00254$.

In summary, the defensible contribution is narrower than some wording in the submission suggested: RankMe is strongly width-confounded in heterogeneous architecture pools, and $\\mathrm{SSR}^{\\ddagger}$ is a lightweight, parameter-free, label-free correction for cross-family selection. It is not a universal replacement for RankMe, reference selection remains an empirical design choice, and we do not claim superiority over label-dependent DiSCO.
